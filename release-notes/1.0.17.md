# Deye EMS 1.0.17 — pierwszy start ładowania i sprawdzanie aktualizacji

Pierwszy start doładowania w tanim oknie nie musi czekać do :00/:30. Wymaga poprawnych pomiarów, potrzebnego doładowania, spełnionych ograniczeń i 120 s stabilnych obserwacji. Dalsze zwykłe korekty zachowują dotychczasowy harmonogram.

Zgoda na pierwszy start jest zapisana dla całego okna taryfowego. Restart, zatrzymanie przez PV i ponowne jego osłabienie nie przyznają kolejnych startów poza harmonogramem. Przy migracji niejednoznaczna historia nie daje automatycznej zgody; jawne przejście z obserwacji do sterowania może jednorazowo nadać brakującą zgodę, po wymaganych kontrolach. Zapis próby poprzedza polecenie, a limity i bieżąca potrzeba są sprawdzane ponownie po zapisie.

Panel pokazuje też wersję rzeczywiście załadowaną przez Home Assistant oraz wersję interfejsu w otwartej karcie. Przycisk **Sprawdź aktualizacje** sprawdza najnowsze publiczne, stabilne wydanie Deye EMS na GitHubie.

- Dostępne nowsze wydanie jest oznaczone w panelu. **Otwórz Marketplace** prowadzi do sklepu tej samej instancji HA; aktualizację instaluje się w natywnym interfejsie HA.
- Starsza karta przeglądarki otrzymuje informację o różnicy wersji i przycisk odświeżenia. Wersja załadowanego modułu nie jest utożsamiana z samą instalacją plików oczekującą na restart.
- Sprawdzenie jest ręczne, oddzielone od regulatora, Solcast i historii. Odczyt statusu, otwarcie panelu i cykliczne odświeżanie nie wysyłają zapytań GitHub. Sprawdzenie nie blokuje zatrzymania sterowania w panelu.
- Krótka przerwa między próbami i obsługa limitów GitHub ograniczają liczbę zapytań. Błąd sieci nie jest prezentowany jako potwierdzenie aktualności; poprzedni wynik jest oznaczony jako nieaktualny.
- Sprawdzenie nie instaluje kodu, nie restartuje HA i nie zmienia ustawień ani trybu EMS. Nie wysyła danych domu lub kluczy API do GitHuba.

Kontrole i ograniczenia opisuje [VALIDATION.md](../VALIDATION.md).
